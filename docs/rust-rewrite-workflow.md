# Rust 改寫工作流程

## 目標

將 `D:\project\artale_auto-master` 的楓之谷補血／補魔工具改寫為 Rust 原生桌面應用程式。保留設定介面、全域快捷鍵、遊戲視窗搜尋、HP／MP 區域選取與自動定位、螢幕擷取、OCR、補水按鍵輸入及 JSON 設定。**不實作自動施放技能**。

採用 UI 主執行緒與背景工作透過訊息佇列溝通的設計：UI 主執行緒獨占所有介面更新；OCR 背景工作負責擷取、辨識、判斷補水並送出狀態事件。停止或關閉時通知工作停止，等待工作結束後再釋放資源。

## 工作階段

### 1. 建立 Rust 應用骨架

- 建立 Cargo 專案與 Windows 桌面啟動流程。
- **本專案決策：** 使用 Windows 原生控制項與 `windows-sys`，不加入 Python 或瀏覽器 UI。由於目前環境無法連線 crates.io，先選用已快取的 crate 與 Win32 API，減少外部依賴。
- 使用 Win32 視窗列舉、GDI 螢幕擷取、`RegisterHotKey`／`WM_HOTKEY`、鍵盤事件與 Tesseract 命令列介接。
- 定義模組邊界：`ui`、`config`、`window_finder`、`capture`、`ocr`、`input`、`monitor`。
- 保持模組可替換；對作業系統能力定義小型介面，讓 OCR 判讀與補水決策可離線驗證。

### 2. 移植設定與基本 UI

- 重建 HP／MP 門檻、遊戲視窗標題前綴、手動區域選取、自動定位選項、補水鍵、狀態與辨識結果顯示。
- 提供 HP、MP 個別啟停控制及同時啟停控制；F6 控制 HP、F7 控制 MP，F5 控制 HP 與 MP。技能相關 UI 和 F8 不納入新版本。
- 載入、儲存、匯入與匯出 JSON 設定；沿用原版 `ocr` 設定欄位，對缺漏欄位套用預設值，遇到無效設定時顯示可理解的錯誤且避免覆寫原檔。
- 舊設定中的 `skills` 欄位會忽略，不移植技能功能；新設定檔只輸出 `ocr` 設定。

### 3. 建立背景工作與生命週期

- 每個 HP／MP 監控工作持有獨立停止訊號，透過事件通道回報狀態、OCR 結果與錯誤。
- UI 定時接收事件並更新畫面，不允許背景工作直接存取 UI 元件。
- 啟動前驗證百分比範圍、目標不低於門檻、補充量大於零，以及按鍵和區域設定。
- 停止、重新啟動與關閉時確保工作退出；按鍵按下後需保證會釋放，即使停止或輸入錯誤也一樣。
- 全域快捷鍵回呼只傳送 UI 命令，不直接操作 UI 元件。

### 4. 移植視窗、擷取與區域定位

- 依標題前綴尋找遊戲視窗，處理視窗不存在、最小化、移動及縮放狀況。
- 支援視窗底部 HP／MP 標籤自動定位，並在視窗幾何變更時重新定位。
- 支援拖曳框選 HP／MP 擷取區域，並將座標轉成一致的螢幕座標格式。
- 將擷取錯誤和定位失敗作為可回報狀態，不讓監控執行緒意外終止。

### 5. 移植 OCR 與補水判斷

- 移植影像灰階、對比／銳化、放大與 OCR 重試流程。
- 移植 HP／MP 數值解析與常見 OCR 字元混淆修正、合理性檢查、最大值穩定確認。
- 低於門檻時送出補水按鍵，並在按鍵後等待數值變化及套用冷卻。
- 將補血與補魔共用可測試的監控邏輯，差異透過設定傳入。
- 評估 Tesseract 的安裝／尋找方式、語言資料需求與錯誤提示；在文件中說明執行前置條件。

### 6. 整合與交付

- 從乾淨環境建置並啟動 Rust 版本，確認設定載入／儲存及程式關閉流程。
- 以遊戲視窗實際確認手動區域、自動定位、HP／MP OCR、全域快捷鍵和補水輸入。
- 確認各監控可獨立啟停、同時啟停，並能在視窗暫時不可用後恢復。
- 記錄建置、執行方式、Tesseract 需求、設定格式與已知限制。

## 每階段完成條件

- 新增或變更的模組有清楚責任，錯誤可回報至 UI，不會讓背景工作靜默消失。
- UI 元件只由 UI 主執行緒更新；所有背景工作都能透過停止訊號正常結束。
- OCR 判讀與補水決策可在不送出真實按鍵的情況下驗證；系統輸入只在明確啟用監控後發生。
- JSON 設定可讀取原版 OCR 設定，儲存失敗時保留既有設定檔。
- 交付前完成上述整合檢查，並記錄尚未支援或仍需使用者環境確認的項目。

## 範圍外

- 技能循環、自動施放技能設定與 F8 快捷鍵。
- OCR 自動定位演算法的準確度調整；改寫時保留該能力並提供錯誤回報即可。
- Python UI 或 Python 與 Rust 的雙程式通訊。
